Deploy and Promote the Pilot Agent Through the Power Platform Pipeline

Sagar Rangi · 2026-10-11T08:36:04 · publish

Categories: Copilot Studio, Copilot Studio &amp; Agent Factory, Power Platform ALM
Tags: Agent Factory, Copilot Studio, Deployment Pipelines, Power Platform ALM

The first Agent Factory runbook stopped at a configured pipeline. This follow-up takes the next step: deploy a managed solution into TEST, verify what arrived, and promote the same release to PROD.

There is an important distinction here. A green deployment result tells us the solution moved successfully; it does not tell us the agent is ready for users. This exercise validates the release path. Agent evaluation, publishing, access approval, and production governance remain separate activities.

Before starting Part 2: Complete Part 1: Building an Agent Factory Pilot — From Copilot Studio Draft to Power Platform Pipeline. You need the pilot agent, the AF Pilot Agent solution, the pipeline host, the linked environments, and the TEST and PROD deployment stages configured before following this walkthrough.

1. Enable Managed Environments for TEST and PROD

Before starting a run, check both target environments. In this pipeline configuration, TEST and PROD need Managed Environments enabled; DEV does not need it solely to act as the development source.

  1. In Power Platform admin center, open Manage > Environments.
  2. Find AF-PILOT-TEST and open its three-dot menu.
  3. If the menu offers Enable Managed Environments, select it and review the settings before choosing Enable.
  4. If the menu says Edit Managed Environments, the feature is already enabled.
  5. Repeat the check for AF-PILOT-PROD.

Enabling Managed Environments is a tenant-governance and licensing decision, not just a switch to make a deployment button work. Use an authorized administrator and confirm the licensing and organizational requirements for your own tenant. The settings below describe this pilot, not a universal production policy.

What changes for PROD?

Use the same pilot settings with these deliberate differences:

  • Turn Editor permissions off. This is the production sharing choice in the lab; it should not be treated as a replacement for role-based access control.
  • Keep Viewer permissions on and allow security groups.
  • Start Solution Checker enforcement at Warn. After a clean deployment, review the findings and agree the enforcement policy before moving to Block.
  • Enable the privacy statement when an approved privacy-policy URL is available and the agent is being prepared for publication to users.

Checkpoint: Both target environments show Managed Environments enabled. Their settings have been reviewed for the pilot, rather than copied blindly into production.

2. Prepare version 1.0.0.3 in DEV

The pipeline should start from the development solution, not from an edited copy in TEST. Give the release a clear version before you run it; that version becomes the simplest way to check that the expected package reached each environment.

  1. Open Power Apps and switch to AF-PILOT-DEV.
  2. Open Solutions > AF Pilot Agent.
  3. Confirm that the package type is Unmanaged.
  4. Open Overview > Edit details.
  5. Set the version to 1.0.0.3 and save.
  6. Select Publish all customizations.

Publishing customizations here prepares the solution components for export. It does not publish the Copilot Studio agent to users.

3. Run the pipeline deployment to TEST

Stay inside the DEV solution for this step. The deployment wizard should identify the release pipeline and the first downstream stage.

  1. Open the solution’s Overview and select Deploy from the command bar.
  2. If the command is not visible, select Pipelines from the solution’s left navigation.
  3. Choose AF-PILOT-Standard-Release.
  4. Select Deploy to TEST, then Deploy here.
  5. Choose Now and select Next.
  6. Wait for preflight validation to finish.

Resolve any requested values in the context of TEST:

  • Choose the TEST connection for each connection reference.
  • Enter TEST-specific environment-variable values.
  • Add a meaningful deployment note, such as Agent Factory pipeline validation – version 1.0.0.3.

Before selecting Deploy, check both the target and the version. The target must be AF-PILOT-TEST and the release must be 1.0.0.3. Do not carry DEV connections or values into TEST just to get past validation.

Monitor the run until it reports success. If preflight validation or deployment fails, stop at that stage and read the recorded error. A failed TEST run is not a reason to try PROD.

4. Verify what arrived in TEST

Check the target environment itself, not only the pipeline’s success indicator.

  1. Open Power Apps or Copilot Studio and switch to AF-PILOT-TEST.
  2. Open Solutions > AF Pilot Agent.
  3. Confirm the package type is Managed.
  4. Confirm the installed version is 1.0.0.3.
  5. Confirm AF-PILOT-DEV-Assistant is present.

The highlighted solution overview shows AF-PILOT-TEST, package type Managed, version 1.0.0.3, and the agent component. That is the evidence this stage is intended to capture.

Do not modify the managed solution in TEST. If a component needs changing, update the source in DEV and deploy a new release. A full conversational evaluation is outside this deployment-path check; success here should not be described as agent-quality or production-readiness approval.

Checkpoint: TEST contains the managed 1.0.0.3 release and the expected agent.

5. Promote the same release to PROD

The production stage follows the completed TEST stage. Promote the release that passed through TEST rather than treating PROD as another independent export.

  1. Return to AF-PILOT-DEV.
  2. Open Solutions > AF Pilot Agent > Pipelines.
  3. Select AF-PILOT-Standard-Release and locate Deploy to PROD.
  4. Confirm that TEST is shown as the completed preceding stage and that its installed version is 1.0.0.3.
  5. Select Deploy here > Now > Next.
  6. Supply PROD-specific connections or environment-variable values if requested.
  7. Review the target and release version, then select Deploy.
  8. Monitor the PROD run until it reports success.
View the PROD deployment sequence

Verify PROD separately

Switch to AF-PILOT-PROD and open Solutions. Confirm that AF Pilot Agent is installed as a managed solution at 1.0.0.3. Open it and check that the expected agent component is present.

The final capture shows AF-PILOT-PROD and the managed AF Pilot Agent solution at 1.0.0.3. Keep the deployment outcome separate from publication: the exercise does not include publishing or sharing the agent with end users.

Record the release evidence

At the end of the run, retain enough evidence to distinguish a successful package promotion from a merely configured pipeline.

  • TEST and PROD are enabled as Managed Environments.
  • The DEV source solution is unmanaged and versioned 1.0.0.3.
  • The TEST stage completed successfully.
  • TEST contains the managed 1.0.0.3 solution and the agent component.
  • The PROD stage follows the completed TEST stage.
  • PROD contains the same managed 1.0.0.3 release.
  • Target-specific connections and variables were reviewed where applicable.
  • Deployment notes and run history are available for later troubleshooting.
