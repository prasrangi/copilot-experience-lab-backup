Building an Agent Factory Pilot: From Copilot Studio Draft to Power Platform Pipeline

Sagar Rangi · 2026-10-10T09:42:18 · publish

Categories: Copilot Studio, Copilot Studio &amp; Agent Factory, Power Platform ALM
Tags: Agent Factory, Copilot Studio, Deployment Pipelines, Power Platform ALM

This runbook covers the full Agent Factory pilot path: create a draft Copilot Studio agent in DEV, move it to TEST as a managed solution, and configure a Power Platform pipeline for future TEST and PROD deployments.

The instructions use the lab resources shown below. Keep the names consistent; the pipeline and validation steps depend on them.

Resource Lab value
Development environment AF-PILOT-DEV
Test environment AF-PILOT-TEST
Production environment AF-PILOT-PROD
Solution AF Pilot Agent
Agent AF-PILOT-DEV-Assistant
Pipeline host AF-PILOT-HOST
Deployment pipeline AF-PILOT-Standard-Release

Lab scope: The agent stays in draft throughout this exercise. Publishing the Dataverse customizations before export does not publish the agent or make it available to users.

Before you begin

  • Use an authorized LAB account with access to Copilot Studio, Power Apps, and Power Platform admin center.
  • Confirm that the DEV, TEST, and PROD environments already exist in the same region and include Dataverse.
  • Use a private or Incognito browser window to avoid switching into the wrong tenant or cached account.
  • Do not add knowledge sources, connectors, tools, workflows, or actions during this initial pilot.

1. Set the preferred solution

Start by making the unmanaged AF Pilot Agent solution the preferred solution in DEV. This ensures that the components created during the lab are added to the correct solution instead of the default solution.

  1. Open a new InPrivate or Incognito browser window.
  2. Go to make.powerapps.com and sign in with your LAB account.
  3. Switch to the AF-PILOT-DEV environment.
  4. Open Solutions, then select the unmanaged AF Pilot Agent solution.
  5. Select Set preferred solution on the command bar.
  6. Confirm that the preferred-solution indicator appears.

Checkpoint: AF Pilot Agent is marked as the preferred solution in AF-PILOT-DEV.

2. Create the pilot agent

Next, create the agent shell in Copilot Studio. At this point, the goal is to establish the component, naming, solution ownership, and instructions. Leave integrations and publishing for a later phase.

  1. In Copilot Studio, select Agents > New agent > Create blank agent.
  2. Name the agent AF-PILOT-DEV-Assistant.
  3. Open Advanced settings before saving and explicitly select AF Pilot Agent as the solution.
  4. Keep the primary language as English (United States).
  5. Create the agent, but do not add knowledge, tools, or integrations, and do not publish it.
Agent creation prompt

Use the following prompt if the agent shell is being created through the GitHub Copilot harness.

Create one draft autonomous agent using the GitHub Copilot harness with these specifications:

Agent name: AF-PILOT-DEV-Assistant
Environment: AF-PILOT-DEV
Existing solution: AF Pilot Agent
Primary language: English (United States)

Purpose:
Act as an internal Agent Factory lab assistant for authorized pilot users. Help users understand the lab deployment process, naming standards, validation checkpoints, testing steps, and safe troubleshooting procedures.

Behavior:
- Give concise, accurate, step-by-step answers.
- Ask a clarifying question when required information is missing.
- Clearly distinguish confirmed information from assumptions.
- Do not invent tenant configuration, test results, policies, users, or business data.
- Do not make administrative changes or modify tenant resources.
- Do not access, expose, or request secrets, credentials, authentication codes, or sensitive personal data.
- Recommend human review before any production, publishing, security, access, or governance change.
- When a request is outside the agent's available information, explain the limitation and recommend the appropriate administrator or owner.

For this initial pilot:
- Create only the draft agent shell and its instructions.
- Use the existing "AF Pilot Agent" solution.
- Do not create another environment or solution.
- Do not use or modify any existing agent.
- Do not add knowledge sources, connectors, tools, workflows, actions, or external integrations.
- Do not publish, deploy, share, or enable the agent.
- If the existing solution cannot be selected automatically, pause and ask me to select it rather than using a default solution.

After creating the draft, summarize the agent name, harness, environment, selected solution, schema name, and whether anything was published.

Checkpoint: The draft agent exists in AF-PILOT-DEV, belongs to AF Pilot Agent, and remains unpublished.

3. Promote the managed solution from DEV to TEST

The next step validates the basic application lifecycle management path. Export the solution from DEV as managed, import it into TEST, and confirm that the agent arrives with its instructions and guardrails intact.

Export from DEV

  1. Leave the evaluation page without saving an evaluation. Evaluation is not required for this stage of the pilot.
  2. In AF-PILOT-DEV, open Solutions > AF Pilot Agent.
  3. Confirm that Objects > Agents contains AF-PILOT-DEV-Assistant.
  4. Select Export solution.

Under Before you export, select Publish all changes, then select Next. This publishes Dataverse customizations into the export package. It does not publish the Copilot Studio agent to users.

Configure the package as follows:

  • Version: 1.0.0.1
  • Export as: Managed

Complete the export and download the resulting ZIP package.

Import into TEST

  1. Switch Copilot Studio to AF-PILOT-TEST.
  2. Open Solutions, then select Import solution.
  1. Select This device > Browse and choose the managed ZIP file.
  2. Select Next. If prompted for environment variables or connections, use TEST-specific values.

Review the import summary, then select Import.

After the import succeeds, open AF Pilot Agent in TEST and confirm:

  • The package type is Managed.
  • Agents (1) is present.
  • The pilot agent opens without errors.
  • The instructions and guardrails were retained.
  • The agent remains unpublished.

Checkpoint: The managed solution and draft agent are available in TEST, with no agent published to users.

4. Create the pipeline host

Power Platform Pipelines needs a host environment where the deployment configuration is stored. Create a dedicated production-type host in the same region as the participating environments.

  1. Open Power Platform admin center > Deployments.
  2. Select New custom host.

Use the following values:

  • Name: AF-PILOT-HOST
  • Type: Production
  • Region: The same region as DEV, TEST, and PROD
  • Dataverse: Yes

Wait for the environment and the Power Platform Pipelines application installation to finish before continuing.

5. Create the deployment pipeline

Once the host is ready, create the release pipeline that will connect the Agent Factory development environment to its downstream targets.

Enter:

  • Name: AF-PILOT-Standard-Release
  • Description: Managed solution deployment from DEV through TEST to PROD

Select Save and Close, then confirm that the pipeline appears in the Pipelines list.

6. Create and link the deployment environments

The pipeline uses deployment-environment records to identify its development source and downstream targets. Start with DEV, then make sure TEST and PROD are also represented.

Create the DEV record

  1. In the open development-environment lookup, select New.
  2. Enter the following values:
    • Name: AF-PILOT-DEV
    • Environment type: Development Environment
    • Environment ID: a4638d0d-888a-e392-953f-76a41cc533f4
    • Description: Agent Factory pilot development environment
  3. Select Save and Close.
  4. Back in the lookup, select AF-PILOT-DEV, then select Add.
  5. Confirm that it appears under Linked Development Environments with Validation Status = Success.

Required environment records

Record Type
AF-PILOT-DEV Development Environment
AF-PILOT-TEST Target Environment
AF-PILOT-PROD Target Environment
7. Create the TEST deployment stage
  1. Select Pipelines from the left navigation.
  2. Open AF-PILOT-Standard-Release.
  3. Under Deployment Stages, select New Deployment Stage.

Configure the stage as follows:

  • Name: Deploy to TEST
  • Deployment Pipeline: AF-PILOT-Standard-Release
  • Target Deployment Environment: AF-PILOT-TEST
  • Previous Deployment Stage: Leave blank
  • Pre-Deployment Step Required: No
  • Is Delegated Deployment: No

Select Save and Close, then confirm that Deploy to TEST appears under Deployment Stages.

8. Create the PROD deployment stage

The PROD stage follows TEST, which establishes the intended promotion order without enabling deployment automation or delegated deployment yet.

  1. Confirm that Deploy to TEST appears under Deployment Stages.
  2. Select New Deployment Stage.
  3. Configure the stage:
    • Name: Deploy to PROD
    • Deployment Pipeline: AF-PILOT-Standard-Release
    • Previous Deployment Stage: Deploy to TEST
    • Target Deployment Environment: AF-PILOT-PROD
    • Pre-Export Step Required: Unchecked
    • Pre-Deployment Step Required: Unchecked for now
    • Is Delegated Deployment: Unchecked
  4. Select Save and Close.

Checkpoint: The pipeline contains a TEST stage followed by a PROD stage. No pre-deployment step or delegated deployment is enabled.

Final validation

  • AF Pilot Agent is the preferred solution in DEV.
  • AF-PILOT-DEV-Assistant exists as an unpublished draft.
  • Managed solution version 1.0.0.1 was imported successfully into TEST.
  • The agent instructions and guardrails are present in TEST.
  • AF-PILOT-HOST is provisioned with Dataverse.
  • AF-PILOT-Standard-Release contains linked DEV, TEST, and PROD environments.
  • The pipeline includes Deploy to TEST followed by Deploy to PROD.
  • Nothing in this runbook publishes the agent to end users.

Production note: Treat publishing, security, sharing, connector configuration, delegated deployment, and governance changes as separate reviewed activities. The pilot deliberately stops before those actions.

Continue to Part 2: Once the agent and pipeline setup above are complete, follow Deploy and Promote the Pilot Agent Through the Power Platform Pipeline to deploy version 1.0.0.3 to TEST, verify the managed solution, and promote the same release to PROD.
